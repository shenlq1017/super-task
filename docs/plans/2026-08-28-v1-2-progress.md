## 本轮（phase 3–7 core、壳层与桌面端入口）做了什么

### 工具链（规格 §4，前置 phase 2）

新建 `crates/supertask-core/src/toolchain/` 并接线进 `lib.rs`（上一轮的未接线草稿已审查、修正、补全）：

- `mod.rs` — `ToolKind`（java|maven|node|npm|pnpm|yarn，`parse`/`as_str`/`path_names`）、`ProviderKind`（mise|winget）。
- `manifest.rs` — 内置 winget 包 ID 映射（版本 manifest v1）；**修正** npm 默认版本映射（原错误地跟随 JDK，现跟随 Node LTS）。包 ID 不由 YAML/UI 传入。
- `provider.rs` — auto 选择（工作区 manager > 用户临时选择；auto：mise→winget，都缺 `TOOLCHAIN_MANAGER_MISSING`，指定的 provider 缺失快速失败不静默换）；固定 argv（winget `--scope user` 无提权参数）；输出分类 `TOOLCHAIN_PERMISSION` / `TOOLCHAIN_INSTALL_FAILED`。
- `runner.rs` — `SpawnSpec` + `ToolRunner` trait；`ProcessRunner` 拒绝 spawn 通用 shell（cmd/pwsh/bash），CREATE_NO_WINDOW，带超时；`FakeRunner` 供测试。
- `resolver.rs` — 安装成功 ≠ 可用：mise 走 `mise which`，winget 刷新进程 PATH（注册表合并，**修正**了多空格行取错值的 bug）后 `find_on_path`；失败一律 `MISSING_TOOL`。`PathProbe` 可注入（测试不依赖真机 PATH）。
- `install.rs` — install/upgrade 主流程：版本校验（复用 YAML 字符集规则 + 禁前导 `-` 防 argv 注入）→ 选择 provider → 固定 argv → 失败保留旧工具与原 YAML（无删除/回滚）→ 成功后立即重新解析。失败消息只保留 stderr 尾行 200 字符摘要。

### 网络（规格 §7）

新建 `crates/supertask-core/src/network.rs`：

- `resolve(workspace, app)` — workspace 字段级覆盖 app 默认；`custom` 必须带显式 URL；URL 复用 YAML 侧 `validate_proxy_url`（http/https、禁 userinfo）→ `PROXY_INVALID`。
- `tool_env` — `off` 不注入；`system` 读 Windows 注册表用户代理（不执行 PAC，读不到直连）；`custom` 用显式 URL；`no_proxy` 始终补齐 loopback（127.0.0.1/localhost/::1）。
- `strip_proxy_vars` — 健康检查等 loopback 调用剥离全部代理键（大小写共 6 个）。
- **未接线**：Maven mirror / npm registry 尚未注入到 launcher 的 Maven/npm 调用（属后续运行时集成）；`EffectiveNetwork.maven/npm` 字段已透传。

### SOON → live + 壳层接线

- `features.rs`：`toolchain.install` / `toolchain.upgrade` 移出 `SOON_COMMANDS`（1.2 已实现，规格 §19）。
- `src-tauri/src/commands.rs`：
  - `toolchain.install` / `toolchain.upgrade` — 扁平参数 `{ tool, version?, manager?, persist?, base_hash? }`；同步快速校验（非法 tool/版本/manager、persist 缺 base_hash 立即拒绝，不发 operation），然后 hub 长操作（kind `toolchain.install` / `toolchain.upgrade`）跑安装；`persist=true` 时装完用 `base_hash` 结构化写回 `toolchain.<tool>`（npm/pnpm/yarn 写 `package_manager`），`YAML_CONFLICT` 时安装结果保留；result 带 `{tool, version, manager, path, hash?}`。代理环境经 `network::tool_env` 注入 provider。
  - `toolchain.probe` — 输出扩展为 `ToolchainProbe`（flatten，前端现有字段不变）+ `managers: {mise, winget}` 可用性。
- `src-tauri/src/lib.rs`：注册 `toolchain_upgrade`。

### 测试（新增约 28 个）

- provider：auto 顺序/工作区覆盖/临时选择覆盖、都缺失报 `TOOLCHAIN_MANAGER_MISSING`、winget argv 不携带用户版本（非法版本 `TOOLCHAIN_VERSION_INVALID`）、权限输出分类。
- install（FakeRunner）：mise 固定 argv、winget fallback argv（`--scope user` 无提权）、权限失败只发生 3 次调用不删除、exit 0 但解析失败 → `MISSING_TOOL`、非法版本零 spawn、upgrade 子命令。
- resolver：注册表行解析保空格值、`mise which` 失败 → `MISSING_TOOL`、env_delta PATH 前插、winget 探针未命中 → `MISSING_TOOL`。
- network：workspace 字段级覆盖、custom 缺 URL / userinfo / 非 http 拒绝、off 零注入、大小写代理键 + NO_PROXY、system 有/无代理、strip、loopback 去重。

- `env-page.tsx` 重写：六工具卡片 + **安装（缺失）/ 升级（已装）/ 重新探测 / 固定到工作区** 四类动作；每卡显示版本来源（工作区要求 → 可改的默认值）。
