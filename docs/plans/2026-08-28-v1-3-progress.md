## 真机修复（2026-08-29，docker 29.7.2 / compose v5.4.0 实测）

docker 29 改了 `--format json` 输出形状，phase 6 的解析器按旧形状写的，真机三处失真（均已修 + 真实输出 fixture 测试）：

1. **compose 插件误判不可用**：新版 `docker compose version --format json` 返回 `{"version":"v5.4.0"}`（小写 `version` 键），旧解析只认 `ComposeVersion` → `DOCKER_COMPOSE_MISSING` 误报。修复：兼容双键；且 `--format json` 非零退出（更旧的 compose 不认识该 flag）时兜底 `docker compose version` 纯文本解析。
2. **镜像列表 `<none>:<none>` / size null / 20693 天前**：docker 29 的 `docker images --format json` 每行是 `Repository`/`Tag` 单值字段（无 `RepoTags`）、`Size` 为人类可读字符串（"194MB"）、`CreatedAt` 为 "2026-08-26 16:46:11 +0800 CST" 人类格式。修复：`parse_images` 双形状兼容（RepoTags 数组 or Repository/Tag；Size 数字 or 人类可读换算 SI/KiB；CreatedAt RFC3339 or 人类格式 → epoch ms，Howard Hinnant 算法共享）。前端 `ImageSummary.size_bytes/created_ms` 改 `number | null`，null 显示「—」。
3. **前端**：表头中文化（容器：服务/容器 ID/镜像/状态/健康/端口；镜像：仓库:标签/镜像 ID/大小/创建时间）；「容器」导航从「未来版本」组移到「主功能」组（registry.ts）；提示文案精简为终态（去掉「容器相关功能已禁用」后缀、各卡片的「需要 Docker 引擎在线」解释与页尾只读边界说明）。
