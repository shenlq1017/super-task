### 2.3 knife4j 真实启动尝试 → 前置条件（非引擎 bug）
引擎正确 spawn `mvn.cmd spring-boot:run`，Maven 开始解析并下载依赖（实测 `knife4j-demo-openapi3` 用 **Spring Boot 4** / `knife4j-spring-boot4`，核心依赖可从 Maven Central 下载，网络正常）。75s 内仍在下载依赖树、未到编译/启动，状态 `Unhealthy`（tcp 8080 未起）。

**真正的硬前置**：该 demo 依赖同级的 **SNAPSHOT** `orivex-boot4-starter:0.1.0-SNAPSHOT`，不在本地仓库、也不在 Central。引擎 1.0 默认 `mvn spring-boot:run`（`module: "."`，无 `-am`）不会构建兄弟模块 → 需先 `mvn install` 整个 reactor（即 yaml 里的 `bootstrap` 脚本 `mvn -q -DskipTests install`）才能 `spring-boot:run` 起来。属项目搭建步骤，**不是引擎缺陷**。

### 环境前置（验证必读）
本机 PATH 上的 `<maven-install>\bin\mvn` 是坏的旧版（classworlds 报错），引擎 `mvn.cmd` 经 PATH 解析会命中它，导致 `spring-boot:run` 必失败。可用安装在 `<maven-install>\apache-maven-3.9.11`。验证前必须：

```bash
export JAVA_HOME="C:/Program Files/Java/jdk-17"
export PATH="<maven-install>/apache-maven-3.9.11/bin:$PATH"
# 然后：cargo run --example real_verify -p supertask-core -- <knife4j_dir> <springapp_dir>
```

> 注：Rust 验证程序是原生 Windows 进程，传入路径须用 Windows 形式（如 `C:/project/...`），不能用 Git-bash 的 `/c/...` 前缀（否则 `fs::canonicalize` 报“找不到路径”）。
