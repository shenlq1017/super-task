## Phase 0 — 计划与复用核查（2026-08-29）

- 实现计划落盘，含对规格 §10 的逐项核实：`rmcp` 已为官方 Tier-1 SDK（2026-08-21 提升，release 2026-08-07，MCP 2026-07-28 spec）；`zip` 当前 v8.6.0（MSRV 1.88，zip-slip 用 `enclosed_name()`）；`ctrlc` 需开 `termination` feature 才覆盖 SIGTERM；工作区锁评估 `fd-lock` 后决定 std-only 零新依赖；pid 存活检测复用 proc 层基础设施（Windows OpenProcess/GetExitCodeProcess，Unix `kill(pid,0)`）。

## Phase 1 — 工作区所有权锁（2026-08-29）

- **任务 1.1** ✅ ErrorCode 新增五枚：`WORKSPACE_LOCKED`、`PKG_NOT_FOUND`、`PKG_INVALID`、`PKG_VERSION`、`PKG_TARGET_EXISTS`（PKG_* 随 Phase 3 使用）。
- **任务 1.2** ✅ `crates/supertask-core/src/lock.rs`：`acquire`（create-new + 同 pid 重入 + stale 接管 + 损坏重建）、`release`（仅删本进程锁）、`query`（只读）；`LockHolder`（desktop/cli/mcp）。`proc/` 平台层新增 `pid_alive`：Windows `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` + `GetExitCodeProcess`，**OpenProcess 被拒（ACCESS_DENIED）视为存活**（与 Unix EPERM 同口径）；Unix `nix::kill(pid, 0)`。7 个单测全绿。
- **任务 1.3** ✅ 引擎接入：`Engine` 增 `holder` 字段（缺省 Desktop，`Engine::with_holder` 供 CLI/MCP）；`open` 打开即取锁（fail-fast 已打开场景；open 失败路径释放锁）；`close`/`detach` 释放。3 个引擎锁生命周期测试。
- **桌面呈现** ✅（最小版）`IpcError` 增 additive 可选 `details` 字段（protocol 1 不变），`WORKSPACE_LOCKED` 的 holder/pid 可达前端；四语 `errors.WORKSPACE_LOCKED` 文案 + `IpcFailure.details`。holder/pid 的富 UI 呈现留待 Phase 2/4 联调时细化。

## Phase 2 — CLI crate（2026-08-29）

- **任务 2.1/2.2 一次性落地**：`crates/supertask-cli`（bin `supertask`），clap v4 derive 全命令（up/down/restart/status/logs/script/export/import/doctor/version）；工作区解析（`-w` > `SUPERTASK_WORKSPACE` > cwd 向上，复用 `strip_verbatim` 清理 verbatim 前缀）；全局 `--json`（信封 `{ok,data|error}`，错误码经 serde 输出与 IPC 同表）；退出码 0/1/2。
- 只读命令不取锁：`status`（yaml + `ports::is_serving` 端口探测 + `lock::query` 显示 owner/pid/alive）、`logs`（复用 `search_logs`/新增 `tail_logs`）、`doctor`（toolchain + docker probe）、`version`。
- 可变命令取锁（`Engine::with_holder(Cli)`）：`up` 拓扑启动（profile 禁用跳过）→ `--wait healthy|started|none`（wait 循环闭包注入可测）→ 交互聚合日志（stderr 流透传 stderr）或 `-- ` 包装（退出码透传）；失败/超时 → `stop_all` + 未达标清单 + `HEALTH_TIMEOUT`；ctrlc(`termination`) 首信号优雅清场、二信号强杀；`down` 幂等、`restart`、`script run/cancel`。
- **Windows 真机冒烟全过**：`up --wait healthy -- cmd /C exit 5` 透传退出码 5；第二进程 `status --json` 正确显示 `lock:{holder:"cli",pid,alive:true}` 与服务 running；`down` 跨进程被拒 `WORKSPACE_LOCKED`（details 带 holder/pid）；强杀 up 进程后 Job Object 清掉 node 桩（端口释放、无残留）；export/import（含 `--with-secrets` 声明文件入包）CLI 往返。
- 已知开发期问题：CLI bin 与 src-tauri dev 产物同名 `supertask.exe`，桌面 dev 进程运行时需 `CARGO_TARGET_DIR=target-cli` 隔离构建（见实现计划偏差 4）。

## Phase 4 — MCP（2026-08-29）

- **任务 4.1** ✅ `crates/supertask-cli/src/mcp.rs`：rmcp 3.1.4（官方 Tier-1）stdio 传输、tools only、无网络监听；7 个工具（status/start/stop/restart/logs/run_script/cancel_script），`tools/list` schema 手工构造（不引 schemars）；统一返回 `{ok,data}` / `{ok:false,error:{code,message,details}}` 错误信封（工具级失败走 `CallToolResult::error`，调用方可见）。
- 业务真源在 `McpServer::dispatch`（可直测），rmcp `ServerHandler` 只做薄封装；tokio 只在 cli crate，引擎调用 `spawn_blocking` 桥接 + `dispatch_lock` 调用级串行化；core 保持纯同步。
- **任务 4.2** ✅ 惰性持有：`supertask_status`/`supertask_logs` 只读不取锁（status 在未打开时退化为文件级只读视图）；首个可变工具经 `Engine::with_holder(Mcp)` 打开并取锁；**断连即清场**：stdio 关闭 → `running.waiting()` 返回 → `stop_all` → `close`（释放锁）→ 退出 0。
- **测试** ✅：dispatch 层 6 个单测（只读不取锁、未知工具、取锁+shutdown 释放、锁冲突传播 WORKSPACE_LOCKED 且只读可用、run_script 缺参、7 工具定义）；stdio 黑盒冒烟：initialize 握手 → tools/list 7 工具 → tools/call 只读快照（正确显示 stale 锁 alive:false）→ 关 stdin exit=0。CLI 总测试 17 个全绿。
- 复用记录：rmcp 3.1.4（2026-08-20 发布）——`ServerHandler` 全默认方法 + `Tool::new` + `CallToolResult::success/error` + `ServiceExt::serve` + `transport::stdio()`；测试策略选 dispatch 直测替代 in-proc transport（transport 层由黑盒冒烟覆盖，避免 rmcp 客户端 API 版本漂移风险）。
